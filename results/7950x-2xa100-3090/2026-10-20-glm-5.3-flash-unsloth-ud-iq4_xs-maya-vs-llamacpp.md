# GLM-5.3-Flash unsloth UD-IQ4_XS: Project Maya vs llama.cpp, and against Maya-L

**Hardware:** [2x A100 SXM4 40GB + RTX 3090, Ryzen 9 7950X, 96 GB DDR5-3600](README.md) ·
**Engines:** [Project Maya](https://github.com/mw00/project-maya) v1.1.17 (`8d9a9b5`), llama.cpp `5aeac37` ·
**Measured with:** [`tools/bench`](../../tools/bench/README.md) · 2026-10-20

## Result

| Model | Engine | Decode | Decode @ 32K | Prefill @ 32K |
|---|---|---:|---:|---:|
| unsloth UD-IQ4_XS (156.8 GB) | Maya, config as below | 38.4 tok/s | 30.1 tok/s | 1,181 tok/s |
| unsloth UD-IQ4_XS | Maya, + `ROUTE_AFFINITY=0.04` | 47.2 tok/s | 37.0 tok/s | 1,169 tok/s |
| Maya-L (156.3 GB) | Maya, same settings | 39.0 tok/s | 30.9 tok/s | 1,165 tok/s |
| Maya-L | Maya, + `ROUTE_AFFINITY=0.04` | **47.5 tok/s** | 37.2 tok/s | 1,155 tok/s |
| unsloth UD-IQ4_XS | llama.cpp, its own fit | 6.4 tok/s | 6.3 tok/s | 135 tok/s |
| unsloth UD-IQ4_XS | llama.cpp, its own fit, `--load-mode none` | 6.5 tok/s | 6.2 tok/s | 142 tok/s |

All six runs in one session, one after another. **On Maya the unsloth quant and Maya-L are a tie**, with and without
route affinity, so picking unsloth's IQ4_XS-based mix over Maya's own IQ3_S-based one (about the same size) costs nothing in speed
here. Route affinity adds +23% to both; its quality cost was measured on Maya-L only
([there](2026-10-20-glm-5.3-flash-maya-l-maya.md#quality-route_affinity-against-the-plain-path)).

**The llama.cpp number is not a tuned one.** Started without `-ngl` / `-ot`, its fit put whole layers on the CPU
(the log: `layer 0 is assigned to device CPU`, and it turned off the fused DeepSeek-V4 "HC post" op because of that),
instead of keeping attention on the GPUs and only some experts in RAM. A hand placement
(`-ngl 999 --n-cpu-moe 18 -ts ...`) ran out of memory at load and wasn't pursued; the files were deleted after this
run. Read it as "llama.cpp's defaults on this box", not as llama.cpp's best.

## Configs

**Maya, unsloth UD-IQ4_XS:** Maya's setup pointed at the downloaded GGUFs writes the pack and the config:

```sh
./maya.sh --setup --gguf-dir /data/models/glm-5.3-flash-unsloth/UD-IQ4_XS --gpus 0,1,2 --context 131072 \
  --draft mtp --no-vision --yes --plain --no-start
```

That is [`configs/maya-ud-iq4_xs-setup.json`](2026-10-20-glm-5.3-flash-unsloth-ud-iq4_xs-maya-vs-llamacpp/configs/maya-ud-iq4_xs-setup.json).
For the bench it got the same hand changes as the Maya-L config, so both quants run with identical settings:

```json
"args": [..., "--vram-reserve-mib", "603", "--vram-reserve-later-mib", "860"],
"env": {"MAYA_GLM_PCIE_SHARE": "0.00", "MAYA_GLM_KV_INT8": "1", "MAYA_GLM_PREFILL_LAND": "12",
        "MAYA_GLM_RAM_HEADROOM_GB": "5",
        "MAYA_GLM_MTP_GGUF": "/data/models/glm-5.3-flash-unsloth/UD-IQ4_XS/mtp-GLM-5.3-Flash-UD-IQ4_XS.gguf"}
```

`MAYA_GLM_MTP_GGUF` points at the NextN block cut out of the GGUF with Maya's `tools/maya_quant/mtp_gguf.py`. It turned
out not to be needed: Maya's pack of the unsloth GGUF keeps blk.45 and uses it as the draft on its own.
(Since v1.1.16 Maya's configs name settings `MAYA_GLM_*`; `maya.py` passes them to the engine under the
`STRATA_GLM_*` names the other pages use. They are the same settings.)

**Maya, Maya-L:** the live `maya-l.json` from the [Maya-L page](2026-10-20-glm-5.3-flash-maya-l-maya.md), with
`exe`/`cwd` pointed at the v1.1.17 build. Every row's exact config is in
[`configs/`](2026-10-20-glm-5.3-flash-unsloth-ud-iq4_xs-maya-vs-llamacpp/configs/).

**llama.cpp:** [`configs/llama-server.sh`](2026-10-20-glm-5.3-flash-unsloth-ud-iq4_xs-maya-vs-llamacpp/configs/llama-server.sh),
the same build as the [Flash-Next page](2026-10-20-qwen3.8-flash-next-strata-vs-llamacpp.md).

## Where it sits

From the engine logs of the two Maya baselines (131K context):

| | CUDA0 (A100) | CUDA1 (A100) | CUDA2 (RTX 3090) |
|---|---|---|---|
| Layers (auto split, both quants) | 0-18 | 19-35 | 36-44 + MTP draft layer |
| VRAM expert pool, UD-IQ4_XS | 34.29 GB (3,053 slots) | 34.73 GB (3,196 slots) | 19.73 GB (1,774 slots) |
| Pinned RAM tier, UD-IQ4_XS | 21.22 GB | 21.78 GB | 15.62 GB |
| VRAM expert pool, Maya-L | 35.05 GB (3,118 slots) | 35.31 GB (3,249 slots) | 20.07 GB (1,719 slots) |
| Pinned RAM tier, Maya-L | 20.55 GB | 21.21 GB | 16.97 GB |

Both fit in VRAM + the RAM tier with no disk reads while answering. As on the Maya-L page the CPU lane is where the time
goes: after the 32K prompt, UD-IQ4_XS computed 56.5 experts per token on the CPU in 27.0 of 33.2 ms; with affinity
0.04, 31.9 experts in 13.5 of 27.0 ms.

## To reproduce

1. Build Maya v1.1.17 in the CUDA container ([hardware page](README.md)) and download `UD-IQ4_XS/` at the revision above.
2. Run the setup command above, add the hand changes, and run [`tools/bench/run-variants.sh`](../../tools/bench/run-variants.sh)
   with `MAYA_BASE` set to that config and a variants file of `maya|glmu_base||` and
   `maya|glmu_aff04|MAYA_GLM_ROUTE_AFFINITY=0.04|`.
3. llama.cpp: set `LLAMA_CMD` to the `llama-server` command in `llama-server.sh` and `LLAMA_PORT=8099`, then run
   `run-variants.sh` with a variants file of `llama|glmu_llamacpp||`.
