# Qwen3.8-Flash-Next quants on Strata: UD-Q4_K_XL vs UD-Q6_K_XL vs Q8_0

**Hardware:** [2x A100 SXM4 40GB + RTX 3090, Ryzen 9 7950X, 96 GB DDR5-3600](README.md) ·
**Engine:** [Strata](https://github.com/Niko1221/Strata) v0.2.0-beta (`3d1fb48`) ·
**Measured with:** [`tools/bench`](../../tools/bench/README.md) · 2026-10-20

## Result

Same engine, same config apart from the file, same client, **same explicit sampling** (temperature 1.0, top_p 0.95,
top_k 20; thinking off), 262,144 context:

| Quant | Size | Experts | Experts in VRAM | Decode | Decode @ 32K | Prefill @ 32K |
|---|---:|---:|---:|---:|---:|---:|
| **UD-Q4_K_XL** | 111.3 GB | 71.7 GiB | 24,509 (all but 67) | **103.0 tok/s** | **104.0 tok/s** | **3,169 tok/s** |
| UD-Q6_K_XL | 169.2 GB | 101.6 GiB | 19,319 (79%) | 78.3 tok/s | 73.8 tok/s | 3,046 tok/s |
| Q8_0 | 188.2 GB | 122 GiB | 16,506 | 60.5 tok/s | 54.3 tok/s | 1,669 tok/s |

**Decode follows how many experts fit in VRAM.** Q4_K_XL fits almost entirely on the three cards; Q6_K_XL leaves
21.7 GiB of experts in RAM, Q8_0 39.3 GiB, and every token that routes to one of those pays for it over PCIe. Prefill
holds up for Q6_K_XL (-4%) and halves for Q8_0, whose prompt path no longer finds its experts in RAM (Strata warns
about it in the log; a 60 GiB RAM budget brings Q8_0 back to 2,387).

On quality, Strata's documentation measures how often each quant picks the same top token as Q8_0: **Q4_K_XL 93.1%,
Q6_K_XL 94.6%**. Not re-measured here. On this box Q6_K_XL costs 24% of the decode speed for 1.5 points of that
agreement; Q4_K_XL is the one I run.

The Q4_K_XL engine comparison (Strata vs llama.cpp on the same file) is on [its own page](2026-10-20-qwen3.8-flash-next-strata-vs-llamacpp.md).

## The files

All from [unsloth/Qwen3.8-Flash-Next-GGUF](https://huggingface.co/unsloth/Qwen3.8-Flash-Next-GGUF). unsloth publishes
no UD-Q8_K_XL for this model; Q8_0 is its only 8-bit quant.

| Quant | Folder, revision | Shards | Routed experts | n-gram table (`per_layer_token_embd`) |
|---|---|---:|---|---|
| UD-Q4_K_XL | `UD-Q4_K_XL/`, `38bb39ee97821de2c9009abb7e93950eec396e66` | 4 | gate/up Q4_K, down Q5_1: 71.7 GiB | IQ4_NL, 26.8 GiB |
| UD-Q6_K_XL | `UD-Q6_K_XL/`, `766911a6b7369840a91dbcd95f9f997acaab6cd6` | 6 | gate/up Q6_K (a few Q8_0), down Q8_0: 101.6 GiB | Q8_0, 50.7 GiB |
| Q8_0 | `Q8_0/`, `766911a6b7369840a91dbcd95f9f997acaab6cd6` | 6 | Q8_0: 122 GiB | Q8_0, 50.7 GiB |

The rest of each model (attention, shared experts, embeddings) is Q8_0, ~5 GiB. Strata reads the n-gram table from
the NVMe with its own row cache in every case, so the table's size changes disk use, not VRAM.

## Configs

Each quant gets its own pack (an index + the small dense tensors, 1.4 GB; the experts are read from the GGUF in
place), built the same way:

```sh
.venv/bin/python tools/iq_pack.py --gguf <shard 1 of the quant> --out packs/<quant> --compat-bf16
```

The MTP draft layer (`mtp/rt`) is the same for all three; its steps are on the
[Strata vs llama.cpp page](2026-10-20-qwen3.8-flash-next-strata-vs-llamacpp.md#strata-setup). The config is the same
for all three apart from `--pack`, `--native` and the tokenizer path
([Q6_K_XL](2026-10-20-qwen3.8-flash-next-quants-strata/configs/strata-ud-q6_k_xl.json),
[Q8_0](2026-10-20-qwen3.8-flash-next-quants-strata/configs/strata-q8_0.json),
[Q4_K_XL](2026-10-20-qwen3.8-flash-next-strata-vs-llamacpp/configs/strata-ud-q4_k_xl.json) with
`--max-context 262144`):

```json
"args": ["--pack", "packs/ud-q6_k_xl",
         "--native", "/data/models/qwen3.8-flash-next/UD-Q6_K_XL/Qwen3.8-Flash-Next-UD-Q6_K_XL-00001-of-00006.gguf",
         "--resident-budget-gib", "40",
         "--expert-profile", "data/expert-profile.bin", "--expert-cache", "auto",
         "--prefill", "auto", "--spec", "4", "--spec-min-p", "0.5",
         "--mtp", "mtp/rt", "--max-context", "262144", "--kv", "int8"],
"gpu": [0, 1, 2], "layer_split": "auto"
```

Strata needs to be built with `-DSTRATA_Q6K_EXPERTS=ON` to serve Q6_K experts (the [hardware page](README.md)'s
build has it).

## Where they sit

| | UD-Q4_K_XL | UD-Q6_K_XL | Q8_0 |
|---|---|---|---|
| Experts resident in VRAM | 24,509 of 24,576 | 19,319 (79%) | 16,506 |
| Experts not in VRAM | ~0 | 21.68 GiB (5,257), all in the 40 GiB RAM budget | 39.25 GiB (8,070), in the RAM budget and the files |
| Lowest MemAvailable | ~71 GiB | ~43 GiB | ~37 GiB |

For Q6_K_XL the 40 GiB budget already holds every expert the GPUs don't, which is why 60 GiB changes nothing for it
(below). For Q8_0 the extra budget mostly helps the prompt path.

## To reproduce

1. Build Strata with `STRATA_Q6K_EXPERTS=ON` ([hardware page](README.md)); download the quant's folder at the
   revision above; run `iq_pack` for it and the MTP steps once.
2. Write the config above with that quant's pack and shard 1, set `"gpu"` to your cards.
3. Run [`tools/bench/run-variants.sh`](../../tools/bench/run-variants.sh) with `STRATA_BASE` set to it and a variants
   file of `strata|fn_strata_q6_262k_t10||`.

With less VRAM than ~104 GB, every quant here moves more experts to RAM and lands lower.
