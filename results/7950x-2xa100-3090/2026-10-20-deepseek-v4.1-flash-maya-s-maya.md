# DeepSeek-V4.1-Flash-1017 Maya-S on Project Maya: 22.4 -> 39.8 tok/s

**Hardware:** [2x A100 SXM4 40GB + RTX 3090, Ryzen 9 7950X, 96 GB DDR5-3600](README.md) ·
**Engine:** [Project Maya](https://github.com/mw00/project-maya) v1.1.16 and v1.1.17 (its DeepSeek engine, `build/maya-ds4`) ·
**Measured with:** [`tools/bench`](../../tools/bench/README.md) · 2026-10-20

## Result

| Config | Decode | Decode @ 32K | Prefill @ 32K |
|---|---:|---:|---:|
| Maya's setup config (+ the prompt fix below), v1.1.16 | 22.4 tok/s | 22.8 tok/s | 506 tok/s |
| v1.1.17, same config | 23.4 tok/s | 23.3 tok/s | 494 tok/s |
| + `--mmap-experts off` | 32.1 tok/s (+37%) | 29.5 tok/s | 430 tok/s |
| **+ `--mmap-experts off --dspark on`** | **39.8 tok/s (+70%)** | **38.6 tok/s** | 421 tok/s |
| + the same with 8,192-token prompt chunks | 37.7 tok/s | 36.3 tok/s | 570 tok/s |

Both changes keep the answers the same: `--mmap-experts off` only changes where the experts live, and DSpark drafts are
checked by the full model.

## The base config

`configs/maya-ds4.json` as Maya's setup wrote it, with one change made by hand: setup wrote `--tp 2`, the engine falls
back to one GPU per layer group ("tensor parallel 2 -> 1", the experts' 256-value blocks don't split), and on v1.1.16
that also turned off chunked prompts (a 19K prompt read at 60 tok/s). `--threads on --prefill-chunk 4096` replaced it.
v1.1.17 fixes this itself (#279).

```json
{
 "exe": "/data/maya/project-maya/build/maya-ds4",
 "args": ["--pack", "/data/models/deepseek-v4.1-flash-1017-maya/Maya-S/maya-ds4",
          "--max-context", "131072", "--dspark", "none", "--threads", "on", "--prefill-chunk", "4096"],
 "gpu": [0, 1, 2],
 "sampling": {"temperature": 1.0, "top_p": 1.0},
 "reasoning_effort": "high"
}
```

`--dspark none` came from Maya's own calibration when the box had 64 GB of RAM: 26.2 tok/s with DSpark against 27.0
without. With 96 GB that reverses (below).

Start (CUDA container, see the hardware page):

```sh
podman run --rm --device nvidia.com/gpu=all --ipc host --network host --ulimit memlock=-1:-1 \
  -v /data/maya:/data/maya -v /data/models/deepseek-v4.1-flash-1017-maya:/data/models/deepseek-v4.1-flash-1017-maya \
  -w /data/maya/project-maya maya-cuda:13.4.3 ./maya.sh --config maya-ds4.json --port 8090 --plain
```

**Requests:** thinking disabled, no sampling fields, so the config's temperature 1.0, top_p 1.0 apply.

## Where it sits

From the engine logs (v1.1.17):

| | default (`--mmap-experts` auto) | `--mmap-experts off --dspark on` |
|---|---|---|
| Layers | 0-13 / 14-28 / 29-39 + head (A100, A100, 3090) | 0-12 + the DSpark blocks / 13-28 / 29-39 + head |
| Experts in VRAM | 3,226 + 3,419 + 1,738 = 8,383 | 2,911 + 3,396 + 1,726 = 8,033 (DSpark takes some VRAM) |
| The rest | ~76.6 GB read in place from the model files, through the page cache (88.6 GB of RAM free: the most-routed read ahead) | 7,711 experts (85.1 GB) on the CPU lane: **7,243 copied into the engine's own RAM (79.9 GB)**, 468 read in place |
| Lowest MemAvailable | ~81 GiB (page cache doesn't count against it) | 5.7 GiB |

With the experts in the page cache, every CPU-lane expert goes through mmap'd pages; copied into the engine's own
memory they compute ~37% faster here. The cost is RAM: 5.7 GiB left, so nothing else big can run next to it.

**Prefill numbers are with a cold page cache** (every variant starts after `drop_caches`), so the 32K prompt also
reads experts and Engram rows from the NVMe. Measured earlier with a warm cache on the same box (64 GB, v1.1.16, 42K
prompt, 4,096-token chunks): 957-990 tok/s.

### What each setting did here

- **`--mmap-experts off`**: +37% decode, -13% prefill. Copies the CPU lane's experts into the engine's memory instead of
  reading them through mmap. Needs the RAM: here 79.9 of the 85.1 GB fit.
- **`--dspark on`** (DeepSeek's DSpark drafter): +19% decode alone, and stacks with the above (+70% together). Drafts
  kept on short answers: 79-96% per draft position. At 64 GB of RAM it was slower than without.
- **`--tp 2` (as setup writes it):** still runs one GPU per layer group, but without `--prefill-chunk 4096` v1.1.17
  picks 8,192-token chunks: +27-35% prefill at -5-7% decode. Worth it for long-prompt work (agents re-reading big
  contexts); for chat the 4,096 chunks decode faster.
- **`--cpu-threads 12`, `DS4_CACHE_THREADS=4`**: no change.
- **v1.1.16 -> v1.1.17**: +4% decode, within noise.

## To reproduce the fastest config

1. Build Maya v1.1.17 ([build steps](README.md#building-project-maya-cuda-sm_80--sm_86)), `./maya.sh --setup` for
   DeepSeek-V4.1-Flash-1017 with `--ds4-quant maya-s`.
2. In the config's `"args"`: `--mmap-experts off --dspark on`, and either `--threads on --prefill-chunk 4096` (faster
   decode) or nothing (v1.1.17 picks 8,192-token chunks: faster prefill).
3. RAM: about 85 GB free for the CPU lane's experts besides ~104 GB of VRAM, or part of them stays on the NVMe.
