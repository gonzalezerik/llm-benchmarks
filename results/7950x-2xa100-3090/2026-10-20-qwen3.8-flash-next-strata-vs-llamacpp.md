# Qwen3.8-Flash-Next on Strata vs llama.cpp: 103 vs 68 tok/s, 3,169 vs 1,068 prefill

**Hardware:** [2x A100 SXM4 40GB + RTX 3090, Ryzen 9 7950X, 96 GB DDR5-3600](README.md) ·
**Engines:** [Strata](https://github.com/Niko1221/Strata) v0.2.0-beta (`3d1fb48`) and
[llama.cpp](https://github.com/ggml-org/llama.cpp) `5aeac37` + PR #30592 ·
**Measured with:** [`tools/bench`](../../tools/bench/README.md) · 2026-10-20

## Result

Same model file (unsloth UD-Q4_K_XL), same box, same client, **same explicit sampling** (temperature 1.0, top_p 0.95,
top_k 20; thinking off), both at 262,144 context:

| Engine | Decode | Decode @ 32K | Prefill @ 32K |
|---|---:|---:|---:|
| llama.cpp | 67.8 tok/s | 68.9 tok/s | 1,068 tok/s |
| **Strata** | **103.0 tok/s (1.52x)** | **104.0 tok/s** | **3,169 tok/s (2.97x)** |

At temperature 0.7 / top_p 0.8 the gap is about the same (100.8 vs 71.7 decode, 3,144 vs 1,061 prefill).

**Why:** Strata keeps **every expert of the Q4_K_XL file in VRAM** across the three cards and reads the 28.8 GB
per-layer n-gram table (`per_layer_token_embd`) from the NVMe with its own row cache. llama.cpp keeps the n-gram table
in RAM (`-ot per_layer_token_embd=CPU`) and splits the rest by layer.

**Q8_0 on Strata** (122 GiB of experts) no longer fits in VRAM: 60.5 tok/s decode, 1,669 tok/s prefill (2,387 with a
60 GiB RAM budget). Q4_K_XL is the one to run on this box.

## Strata setup

Build: [hardware page](README.md#building-strata-cuda-sm_80--sm_86). Then, in the checkout:

```sh
# the pack: an index + the small dense tensors (1.4 GB); the experts are read from the GGUF in place
.venv/bin/python tools/iq_pack.py --gguf /data/models/qwen3.8-flash-next/UD-Q4_K_XL/Qwen3.8-Flash-Next-UD-Q4_K_XL-00001-of-00004.gguf \
  --out packs/ud-q4_k_xl --compat-bf16
# the MTP draft layer (range-reads only the mtp.* tensors of Qwen's BF16 checkpoint, pinned revision, sha256-checked)
.venv/bin/python tools/mtp_fetch.py fetch --out mtp
.venv/bin/python tools/mtp_fetch.py verify --out mtp
.venv/bin/python tools/mtp_pack.py --src mtp --experts q2_0 --out mtp/mtp-q2_0.gguf
.venv/bin/python tools/mtp_rt.py --gguf mtp/mtp-q2_0.gguf --out mtp/rt
cp data/draft_vocab.bin mtp/rt/draft_vocab.bin
```

Config ([`configs/strata-ud-q4_k_xl.json`](2026-10-20-qwen3.8-flash-next-strata-vs-llamacpp/configs/strata-ud-q4_k_xl.json);
the 262K rows set `--max-context 262144`):

```json
{
 "exe": "build/strata",
 "args": [
  "--pack", "packs/ud-q4_k_xl",
  "--native", "/data/models/qwen3.8-flash-next/UD-Q4_K_XL/Qwen3.8-Flash-Next-UD-Q4_K_XL-00001-of-00004.gguf",
  "--resident-budget-gib", "40",
  "--expert-profile", "data/expert-profile.bin", "--expert-cache", "auto",
  "--prefill", "auto", "--spec", "4", "--spec-min-p", "0.5",
  "--mtp", "mtp/rt", "--max-context", "131072", "--kv", "int8"
 ],
 "cwd": ".",
 "tokenizer": "packs/ud-q4_k_xl/tokenizer",
 "model_name": "qwen3.8-flash-next-ud-q4_k_xl",
 "gpu": [0, 1, 2],
 "layer_split": "auto"
}
```

Start (in the CUDA container, see the hardware page):

```sh
podman run --rm --device nvidia.com/gpu=all --ipc host --network host --ulimit memlock=-1:-1 \
  -v /data/strata:/data/strata -v /data/models/qwen3.8-flash-next:/data/models/qwen3.8-flash-next:ro \
  -w /data/strata/Strata maya-cuda:13.4.3 \
  .venv/bin/python -m serve.server --engine strata --config strata-ud-q4_k_xl.json --host 127.0.0.1 --port 8090
```

Where it put things (engine log): the split search placed layers 0-4 on the RTX 3090 and 5-26 / 27-47 on the A100s;
**24,509 of the 24,576 profiled experts are resident in VRAM** (11,264 + 10,685 slots on the A100s, 2,560 on the
3090), so the 40 GiB RAM budget holds almost nothing. The n-gram table is read with direct NVMe reads (probe: 76,409
rows/s). Lowest MemAvailable during the runs: ~71 GiB.

For Q8_0 the same config with `packs/q8_0` (packed the same way from the Q8_0 shard 1): layers 0-7 / 8-27 / 28-47,
16,506 experts resident (98.9% of the routed weight by Strata's profile); the rest comes from the RAM budget and the
files.

## llama.cpp setup

The exact command: [`configs/llama-server.sh`](2026-10-20-qwen3.8-flash-next-strata-vs-llamacpp/configs/llama-server.sh).
In short: all layers on the GPUs split 36/40/24, the n-gram table on the CPU, MTP draft (3 tokens) on the first A100,
q8_0 KV, 262K context, flash attention, `-ub 1536`. It is the best of a tuning pass on this box: `-ub 2048` does not
fit, `-sm row` / `-sm tensor` fail, UD-IQ4_XS is +13% prefill but -8% decode, MTP doubles decode (54 -> 114 tok/s on
greedy code) for -17% prefill.

Notes:

- `--spec 6` (up to 5 drafts per round instead of 3) is not faster than the default 4.
- 131K and 262K context are the same speed on Strata (the KV cache is INT8 and small for this model).
- llama.cpp's `"thinking": {"type": "disabled"}` handling was not verified; its answers may include reasoning tokens.
  They are counted like any other output token, so the decode rate is still comparable.
- Strata's documentation measures Q4_K_XL at 93.1% the same top token as Q8_0 (Q5_K_XL and Q6_K_XL: 94.6%). The
  quality of the two engines on the same file: Strata reports 97.5-99% top-1 agreement with llama.cpp on short answers
  ([its UNSLOTH_Q4.md](https://github.com/Niko1221/Strata/blob/v0.2.0-beta/docs/UNSLOTH_Q4.md)). Not re-measured here.

## To reproduce

1. Build Strata (hardware page), download `UD-Q4_K_XL/` from the repo above, run the pack and MTP steps.
2. Write the config above, set `"gpu"` to your cards. Strata only splits a model across cards of one make.
3. Start the server. It answers on `/v1/messages` (Anthropic) and `/v1/chat/completions` (OpenAI).

To match the numbers it needs ~72 GiB of experts + ~5 GiB of dense weights in VRAM across the cards, so about 80 GB or
more of VRAM. With less, part of the experts move to the RAM budget and decode drops toward the Q8_0 numbers.
