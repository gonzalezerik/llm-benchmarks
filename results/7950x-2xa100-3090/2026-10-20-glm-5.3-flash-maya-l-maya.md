# GLM-5.3-Flash Maya-L on Project Maya: 38.5 -> 47.7 tok/s

**Hardware:** [2x A100 SXM4 40GB + RTX 3090, Ryzen 9 7950X, 96 GB DDR5-3600](README.md) ·
**Engine:** [Project Maya](https://github.com/mw00/project-maya) v1.1.16 and v1.1.17 ·
**Measured with:** [`tools/bench`](../../tools/bench/README.md) · 2026-10-20

## Result

| Config | Decode | Decode @ 32K | Prefill @ 32K |
|---|---:|---:|---:|
| Maya's own config (setup + hand tuning), v1.1.17 | 38.5 tok/s | 29.3 tok/s | 1,175 tok/s |
| + `STRATA_GLM_ROUTE_AFFINITY=0.02` | 44.2 tok/s (+15%) | 33.7 tok/s | 1,165 tok/s |
| **+ `STRATA_GLM_ROUTE_AFFINITY=0.04`** | **47.7 tok/s (+24%)** | **37.0 tok/s** | 1,168 tok/s |

`ROUTE_AFFINITY` **changes the model's output slightly** (it favours experts that are already in VRAM when the router
picks a token's 8 experts). How much is measured under [Quality](#quality-route_affinity-against-the-plain-path).
Nothing else tried here helped by more than 3%.

## The model

| | |
|---|---|
| Model | [zai-org/GLM-5.3-Flash](https://huggingface.co/zai-org/GLM-5.3-Flash): 320B total / 18B active, 45 layers, 288 routed experts (top-8) + 1 shared |
| Quant | **Maya-L** from [peasantsmith/GLM-5.3-Flash-Maya-GGUF](https://huggingface.co/peasantsmith/GLM-5.3-Flash-Maya-GGUF), folder `Maya-L`, revision `f16ee4ba50d8fd2bb726ea1862ca6ca14ba188da`: 4 shards, 156.3 GB (145.6 GiB), IQ3_S-based mix. The model's own MTP block is the draft. |
| Files on disk | `Maya-L/GLM-5.3-Flash-Maya-L-IQ3_S-0000{1..4}-of-00004.gguf`, plus `Maya-L/pack/` (Maya's index + tokenizer, written by its setup) |

Maya's setup (`./maya.sh --setup`, choosing Maya-L with the MTP draft) downloads the shards, writes the pack and the
config. Vision files exist but no images were sent in these runs.

## Where it sits on this box

From the engine log of the v1.1.17 baseline (131K context):

| | CUDA0 (A100) | CUDA1 (A100) | CUDA2 (RTX 3090) |
|---|---|---|---|
| Layers (auto split) | 0-18 | 19-35 | 36-44 + MTP draft layer |
| Dense weights + KV + buffers | 3.88 GB | 3.37 GB | 2.68 GB |
| VRAM expert pool | 35.05 GB (3,118 slots) | 35.31 GB (3,249 slots) | 20.07 GB (1,719 slots) |
| Pinned RAM tier | 20.55 GB | 21.21 GB | 16.97 GB |
| One RAM-tier expert on the CPU / over PCIe | 0.353 / 0.972 ms | 0.261 / 0.874 ms | 0.441 / 1.736 ms |

The VRAM pools hold 8,086 expert slots and the pinned RAM tier 5,259 (58.7 GB); at start the tiers load all 12,384
experts (148.5 GB) between them, so **no expert is read from the SSD while answering** (`disk 0.00 reads/tok`). The CPU computes every RAM-tier expert (14 threads; it beats PCIe on every
card), and that is the bottleneck: in the baseline the CPU lane takes 17.4 of 25.9 ms per token (37.5 experts per token).

The RAM speed matters here. In an earlier run on this box with only the two 32 GB DIMMs (64 GB, running faster than
3600 MT/s; the exact speed wasn't recorded), v1.1.15, 262K context and Maya's own `--bench` (greedy, different prompts),
a CPU expert took 0.18-0.20 ms instead of 0.26-0.44 ms, but the 64 GB could not hold all experts and 2.3 per token
came from the SSD; decode was 41.0 tok/s there. The 96 GB at 3600 MT/s removed the SSD
reads and slowed the CPU lane by about the same amount.

## How it was run

Each variant is Maya's config below plus the listed changes, started fresh in the CUDA container:

```sh
podman run --rm --device nvidia.com/gpu=all --ipc host --network host --ulimit memlock=-1:-1 \
  -v /data/maya:/data/maya -v /data/models/glm-5.3-flash-maya:/data/models/glm-5.3-flash-maya \
  -w /data/maya/project-maya maya-cuda:13.4.3 ./maya.sh --config maya-l.json --port 8090 --plain
```

The base config (`configs/maya-l.json`, written by Maya's setup, then hand-tuned on this box when it had 64 GB:
131K context instead of 262K, INT8 latent KV cache, a smaller prompt landing ring, the VRAM reserves):

```json
{
 "exe": "/data/maya/project-maya/build/strata",
 "args": ["--glm-pack", "/data/models/glm-5.3-flash-maya/Maya-L/pack",
          "--max-context", "131072", "--expert-cache", "auto", "--prefill", "auto", "--kv-streaming", "on",
          "--expert-profile", "/data/maya/project-maya/data/expert-profile-glm.bin",
          "--vram-reserve-mib", "603", "--vram-reserve-later-mib", "860"],
 "gpu": [0, 1, 2],
 "sampling": {"temperature": 1.0, "top_p": 0.95},
 "reasoning_effort": "high",
 "env": {
  "STRATA_GLM_SLOT_KEEP": "1",
  "STRATA_GLM_PCIE_SHARE": "0.00",
  "STRATA_GLM_KV_INT8": "1",
  "STRATA_GLM_PREFILL_LAND": "12",
  "STRATA_GLM_RAM_HEADROOM_GB": "5",
  "STRATA_GLM_USAGE": "/data/maya/usage/glm-5.3-flash.txt"
 }
}
```

(Shortened: tokenizer, vision, lib_dirs and installer fields are in the file.) For the bench, `STRATA_GLM_SLOT_KEEP`
and `STRATA_GLM_USAGE` were removed, so no variant starts with conversations or routing statistics a previous one
left behind; the v1.1.17 runs point `exe` and `cwd` at the v1.1.17 build (`build/maya`). Every row's exact config is in
[`configs/`](2026-10-20-glm-5.3-flash-maya-l-maya/configs/).

**Requests:** thinking disabled, no sampling fields, so Maya's config applies: temperature 1.0, top_p 0.95.

### What each setting did here

- **`STRATA_GLM_ROUTE_AFFINITY=b`** (v1.1.17, PR #252; opt-in): adds `b` to the selection score of experts already in
  VRAM; their weights stay their own probabilities. Engine log, short answers: VRAM hits 90.4% -> 92.3% (0.02) ->
  93.1% (0.04), CPU-lane experts per token 37.5 -> 29.8 -> 27.1. That is the whole gain, since the CPU lane is the
  bottleneck. Changes the output.
- **`STRATA_GLM_RAM_RESIDENT=1`**: holds every non-VRAM expert in RAM and never evicts to the SSD. With 96 GB the default
  tier already held all of them, so no speed change; it pins ~8 GB more RAM (MemAvailable 12 instead of 20 GiB).
- **DFlash2 drafter** (Anbeeld/GLM-5.3-Flash-DFlash2-GGUF, Q4_K_M) instead of the MTP block: Maya measures both at the
  first start and keeps the faster one. Here: **DFlash2 36.4 vs MTP 35.9 tok/s** (+1.4%, under its 5% bar, 47% of
  DFlash2's drafts accepted against ~83% for MTP), so it kept MTP. The 352 s load is that calibration.
- **`STRATA_GLM_DEFER_CPU=1`** (v1.1.17, PR #252; opt-in, changes the output): adds a layer's CPU-lane experts after the
  next layer's attention, so the CPU overlaps it. Only applies to the first GPU's layers on a split, hence +3% at most,
  and nothing on top of affinity.
- **`STRATA_GLM_CPU_LANE`** (threads for RAM-tier experts, default 14 here): 10 threads +0-2% decode, -3% prefill; 8
  threads no change. The RAM, not the cores, limits the CPU lane at 3600 MT/s.
- **`STRATA_GLM_PROMOTE_MIN=6`**: -4%. Helps where experts churn between tiers, not here.
- **v1.1.16 -> v1.1.17**: same speed within noise for this model on these cards (v1.1.17's GLM changes are mostly for
  Volta GPUs and short prompts on one GPU).

## To reproduce the fastest config

1. Build Maya v1.1.17 for your cards ([build steps](README.md#building-project-maya-cuda-sm_80--sm_86)), run
   `./maya.sh --setup`, choose Maya-L.
2. Add to the config's `"env"`:
   ```json
   "STRATA_GLM_ROUTE_AFFINITY": "0.04"
   ```
   (or `0.02`, see the quality numbers above).
3. Start: `./maya.sh --config maya-l.json`.

What it needs to match these numbers: about 104 GB of VRAM across the cards plus ~59 GB of RAM free for the pinned
tier, so that nothing comes from the SSD. With less RAM, part of the experts stream from the SSD and the RAM-tier
settings above behave differently.
